# CUMCM 图形 MCP 路由与插入契约

本规则把“是否需要图、使用哪类图、何时插入正文”与具体绘制分离。正式论文图依次经过
`paper-figure-router`、绘图后端、注册表与最终页面审查；不得先画图再为它寻找正文位置。

## 可用后端

| MCP | 职责 | 正式源文件 |
|---|---|---|
| `paper-visio` | 问题关系、模块结构、算法判断与反馈流程 | `.vsdx` |
| `paper-tikz` | 坐标、角度、尺寸、切线、投影、碰撞边界和公式几何 | `.tex` |
| `paper-matlab` | 时间响应、轨迹、曲面、参数扫描、收敛、敏感性和验证图 | `.m` |
| `paper-figure-router` | 判断插图必要性、后端、图型、正文位置与证据要求 | 路由 JSON |

三种绘图后端均输出 PDF/SVG 矢量成品。Visio 还必须输出同名 `.layout.json`，并在实际论文
宽度下完成视觉复核；未完成复核时 `publication_ready=false`，不得进入正文。

调用后端前必须执行对应 MCP 的 `health_check` 并登记结果；配置中出现名称不等于实际可用。若 `paper-figure-router` 不可用，可以按本文件的确定性规则回退，但必须记录 `router_mode: deterministic_fallback`，不得伪称调用过路由 MCP。每图须登记 renderer、tool、spec、provenance manifest；安装了三种 MCP 不等于生成了三软件混合图。

PDF/SVG 必须核验为真矢量而非整页位图。Visio 合成 MATLAB/TikZ SVG 时按源 `viewBox` 或原始宽高等比放置，`abs(output_ratio/source_ratio - 1) > 0.002` 直接阻断。MATLAB/TikZ/Visio 均须保留实际插入尺寸、整页、缩略和灰度渲染；Visio 使用 `record_visual_review` 关闭视觉门禁，复合图必须审查最终复合成品。

## 插图判定

调用 `route_figure` 前写清：章节、唯一待证明命题、对象数量、关系步骤、判断或反馈、几何约束、
数据维度以及是否与现有图重复。返回 `should_insert=false` 时保留文字、公式或表格，不调用绘图后端。

- 问题重述、模型假设、符号说明、参考文献和附录默认不插正式论证图。
- 问题分析章仅在三个以上分问或对象存在共享输入、输出或递进时插关系图，位置在依赖说明之后。
- 建模求解中，精确坐标或几何判据图放在对象与坐标定义之后、首个控制方程之前。
- 有三个以上不可合并步骤且含判断、回退或状态转移时插 Visio 流程图；普通线性步骤不画。
- 数据结果图放在提出待检验命题的句子之后、关键读数与机理解释之前。
- 验证图只展示误差、收敛、敏感性、不确定性或独立复算，不重复主结果图。
- 模型评价不新增装饰图；已有证据用文字概括适用范围与失效条件。

## 绘制与插入顺序

1. 从证据矩阵抽取唯一 `claim_id` 和待证明命题。
2. 调用 `paper-figure-router.route_figure`；记录是否插图、后端、图型、正文位置和所需输入。
3. 按路由调用 `paper-visio.render_diagram`、`paper-tikz.render_geometry`/`compile_tikz` 或
   `paper-matlab.render_figure`/`render_scene3d`。
   - TikZ 需要局部放大时，优先在结构化 spec 中使用 `detail_inset`：必须提供 source ROI、inset
     位置/尺寸、放大比例和 inset 内原生矢量图元。ROI 与 inset 使用同一对象语义与颜色映射；禁止
     截图裁块、栅格贴片或白底公式图片。放大窗至少解释一个主图不能清楚读取的判据。
   - Visio 需要通用高级流程视觉时，优先使用 `visual_preset: editorial-spine` 并指定
     `focus_node`。预设只提供跨题型的主轴、阶段徽标、线宽层级、判断色与反馈层级，不得把某题节点
     或坐标硬编码进预设。
   - **GGB 几何源与 `paper-tikz` 清洗中间件（Sanitizer Contract）**：将 GeoGebra (GGB) 或外部图形工具导出的切点、可行域或物理机理路径传入 `paper-tikz` 编译前，必须先执行提纯过滤：① 把坐标精度统一舍入至 **2--3 位有效小数**；② 去除多余的 `\clip rectangle` 裁剪区域及临时色彩（如 `ududff`、`uuuuuu`）；③ 将图元样式与标签分离并映射到 `cumcm` 统一样式表，避免生成臃肿代码或文字重叠碰撞。
4. Visio 正式图使用 `strict_audit=true`，每条边填写 `id`、`kind`、`meaning`、方向和分支文字；
   节点文字写入形状自身，普通框白底直角，判断框标准菱形，颜色不承担流程语义。
5. 在原尺寸、论文宽度、缩略图和灰度视图复核。Visio 用 `record_visual_review`关闭视觉门禁；
   TikZ/MATLAB按对应审计脚本登记可读性、矢量性和数据追溯。
6. 写入 `审查/diagram-registry.json` 或 `审查/figure-registry.json`，再运行风格审计。
7. 图前只提出对象、条件和读数；图后依次写观察、关键数值、原因及其对当前结论的影响。

## 流程图视觉约束

- 默认白底、深灰线与黑色文字；不使用颜色编码、渐变、阴影、图标或大面积浅蓝填充。
- 主轴优先纵向，5--8个关键节点；“否”分支放在主轴一侧，反馈沿画布外缘回到真实更新节点。
- 普通步骤使用直角矩形，起止使用小圆角矩形，判断使用标准菱形。
- 每个节点一至两行、单一字号，文字与框为同一对象；不采用“大标题+小字说明”卡片。
- 分支文字靠近对应第一段连线，不压菱形、箭头或节点；所有箭头终止于目标边界。
- 自动布局失败时允许显式提供坐标和路径，但仍须逐连接审计，不得用屏幕拖动修正数值几何。
- `editorial-spine` 的阶段徽标必须是 Visio 原生矢量对象；焦点徽标和普通徽标语义有别，但不得遮挡
  节点或连接。连接审计通过后仍要在论文实际宽度和 25% 缩略图检查主轴、判断、反馈和输出。

## 特色主视觉图的多后端组合

特色图仍先经过插图判定，并先选 `visual-identity-and-archetypes.md` 中的证据原型。需要复合表达时，允许以下可验证组合：

- MATLAB 负责全部数值几何、曲线、场、等值线和统计分布；
- TikZ 负责精确几何、公式关系、局部放大和尺寸/阈值标注；
- Visio 只负责高层结构编排和可编辑版面，不重绘或手工移动数值点；
- 单一后端能完整表达时优先单后端，禁止为了“混合三软件”增加无意义流程；
- 复合图必须登记每个面板的 renderer、源文件、viewBox、最终比例和组合顺序，并审查最终复合页；
- 特色图采用共享视觉身份：白底、深灰文字、冷蓝主色、青绿辅助、单一橙红结论色，但同一变量的颜色仍以全文语义一致性优先。

## 失败处理

- 路由判定不需要图：删除候选图，不以美观为由保留。
- 后端生成成功但审计失败：修改结构化 spec 或样式规则后重跑，不在导出文件上手工补丁。
- 图与正文结论不一致：以证据为准，回到结果或模型阶段；不得改动数据点迎合文字。
- 改变字体、画布、连接、标签或插入宽度：重开图形门禁和引用章节门禁。
