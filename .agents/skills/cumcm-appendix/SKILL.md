### 规范写作纪律

1. **绝对禁止泄漏个人/学校/赛号/博主信息**（一票否决红线）。
2. **代码必须使用等宽字体（Consolas / Courier New）**，且每一行代码控制在 75 字符以内，避免超宽被 PDF 边距截断。
3. **正文与附录代码结果 100% 双向一致**，严禁伪造跑不通的代码。

## 内容顺序

1. 支撑材料清单：相对路径、用途、对应问题；
2. 按问题或功能模块组织的完整可运行源程序；
3. 真实运行环境、依赖版本、输入输出约定与复现命令；
4. 正文放不下但核查结论所需的补充推导、表格或诊断；
5. 必要的数据字段说明，不重复题目原始数据。

## 支撑材料清单模板

附录开头用表格建立索引：

```text
| 序号 | 文件/模块 | 用途 | 对应问题 | 运行方式 |
|------|----------|------|---------|---------|
| 1    | Q1_solve.py | 问题一主求解 | 问题一 | python Q1_solve.py |
| 2    | Q2_optimize.py | 问题二优化 | 问题二 | python Q2_optimize.py |
| 3    | utils.py | 公共工具函数 | 所有 | 被其他脚本导入 |
```

## 代码组织模式

按问题分组，每组遵循以下结构：

**功能说明**（2–3 句）：
- 本程序解决什么问题，对应正文哪个模型/算法
- 主要输入和输出是什么
- 对应正文公式编号（如有）

**完整代码**：
- 不得使用省略号、伪代码占位或"此处省略"
- 无法解析的外部绝对路径替换为相对路径
- 输入输出与论文结果一致，随机过程固定种子

**预期输出**（可选）：
- 给出关键结果的预期数值或文件名
- 便于评委核验代码真实性

## 代码内注释规范

关键函数头部使用结构化注释：

```python
def solve_q1(data_path, c=10000):
    """
    问题一：波浪能装置垂荡运动求解
    输入：data_path - 附件数据路径
          c - 直线阻尼系数 (N·s/m)
    输出：displacement - 浮子位移序列 (m)
          velocity - 振子速度序列 (m/s)
    对应：正文式(3)-(5), 表1
    """
```

普通代码行只在关键算法步骤、非显然参数和容易误解处添加注释。
不需要每行都注释，也不需要长段文字解释。

```text

- 问题一：python Q1_solve.py（预计运行 < 30 秒）

```

不得只写宽泛的"需要 Python"或"MATLAB 环境"。

## 正文与附录边界

正文必须自洽地给出模型、关键推导、参数和最终结果。附录承担复现与补充证据，不能替代正文论证。

| 归属正文 | 归属附录 |
|---------|---------|
| 核心公式推导 | 完整代码实现 |
| 模型建立逻辑 | 补充性推导细节 |
| 关键结果和验证 | 大体量结果表 |
| 参数选择依据 | 运行环境和命令 |
| 图表及其解释 | 支撑材料索引 |

正文不反复写"完整程序见附录"、文件名、代码入口或运行命令。
附录内的代码与正文数值必须完全一致，种子固定后可重跑。
