# CUMCM 问题分析

先完整读取 [../cumcm-paper/references/section-chain-contract.md](../cumcm-paper/references/section-chain-contract.md)、
[../cumcm-paper/references/front-section-content-standard.md](../cumcm-paper/references/front-section-content-standard.md) 与
[../cumcm/references/model-selection-and-answer-quality.md](../cumcm/references/model-selection-and-answer-quality.md)。
论证叙事同时遵守 [../cumcm/references/argumentation-patterns.md](../cumcm/references/argumentation-patterns.md)：
每段只承担一个职责，连接词承载因果而非装饰，跨问衔接写在后问开头。
使用 [../cumcm-paper/assets/latex-template/analysis.tex](../cumcm-paper/assets/latex-template/analysis.tex)
作为标题和段落模板。需要章末关系图或流程图时调用 `cumcm-diagrams`，完整遵守其 TikZ / Visio 规范。

## 输入

- 已通过门禁的问题重述；
- 数据结构、物理机理、约束关系和歧义处理结论；
- 实际采用的模型路线、求解步骤和必要的模型选择证据；
- 各问的输入、输出、共享变量及验证安排。

缺少真实求解路线时不得凭常识编写“拟采用”的过程，应退回求解阶段补齐。

## 固定成稿结构

默认按分问设置二级标题：

```text
二、问题分析
2.1 问题一的分析
2.2 问题二的分析
……
```

- LaTeX 中写 `\section{问题分析}` 与 `\subsection{问题一的分析}`；模板类自动生成“二、”和“2.1”等编号，不手写编号。
- 每问原则上只设一个二级标题，分析思路与求解过程写成连续自然段，不机械拆出“分析思路”“求解过程”等三级标题。
- 各问连续排版，不强制换页。
- 问题之间确有共享输入、前后承接、并行汇合或反馈时，可在各问分析之后放置一幅“各问题关系与总体求解流程图”；该图通常不另设空洞标题。

## 优秀论文规范表达范本与防 AI 味指南（基于 50 篇语料）

在 50 篇优秀论文中，问题分析是展现**学术推理功底与数理转化能力**的核心部分，严禁写成“先干啥、后干啥、用了什么先进算法”的流水账。

### ❌ AI 味典型表达 vs ✅ 50 篇优秀论文规范表述

| 维度 | ❌ AI 味套路流水账 | ✅ 优秀论文规范学术推演（50 篇对标） |
|---|---|---|
| **特征判别** | “针对问题一，首先我们对数据进行了预处理，发现数据具有非线性的特征，因此需要建立复杂的模型。” | “问题一要求求解浮子与振子在波浪力作用下的动态响应。系统受力包括波浪激励力、静水恢复力及 PTO 阻尼力，本质上属于**二阶非线性耦合常微分方程初值问题**。” |
| **思路转化** | “为了求解这个问题，我们建立了优化模型，并编写了先进的遗传算法来进行搜索，效果非常显著。” | “分析思路分为两步：首先由牛顿第二定律构建垂荡方向的受力平衡方程；其次将连续连续微分方程转化为一阶微分方程组，利用四阶 Runge-Kutta 算法在时域内离散迭代。” |
| **算法与步骤** | “我们利用 MATLAB 软件调用了内置的函数进行求解，经过多轮迭代得到了精确的解。” | “求解时取步长 $\Delta t = 0.01\,\text{s}$，逐步更新浮子与振子的位移与速度状态矢量，利用稳态后 $t \in [10, 40\,\text{s}]$ 内的数值解提取能量做功。” |
| **跨问衔接** | “问题二在问题一的基础上更加复杂，我们继续使用上述方法，为后续建模奠定了坚实基础。” | “问题二继承问题一的运动方程组，将阻尼系数 $c$ 由常数升级为决策变量。目标函数调整为平均输出功率 $\bar{P}(c)$，转变为**单目标非线性数值优化问题**。” |

### 规范写作纪律

1. **拒绝“流水账”与“软件操作说明”**：严禁在分析中写“打开 MATLAB/Python 导入数据”、“点击求解按钮”等操作细节。
2. **拒绝空泛高大上词汇**：严禁使用“先进的算法”、“强大的优化器”、“极其精准的分析”。
3. **突出数理映射**：每一个分析段落都必须体现“物理/业务现象 $\rightarrow$ 数理方程/算法机制”的精确映射。

## 每问写作顺序

围绕当前问题按以下逻辑组织，但不得机械写成四条清单：

1. **特征判断**：指出决定处理方向的数据结构、物理关系、几何关系、约束或决策机制。
2. **分析思路**：说明需要把原问题转化为什么可处理的对象，关键量如何关联，以及为何沿这条路线处理。
3. **求解过程**：按真实执行顺序交代输入整理、关系建立、参数求取、数值计算、优化搜索、判定或复核等关键环节，并说明相邻步骤之间传递什么。
4. **衔接关系**：说明本问产生的量如何形成当前问题的答案，或如何作为后续问题的输入；若各问独立，直接结束，不强造联系。

对机理、几何或控制问题，必须显式形成“物理对象与坐标系 → 主导作用或几何约束 → 状态量/决策量 → 控制关系 → 数学对象 → 待求输出 → 主要误差来源”的物理—数学转化链。不得从题面特征直接跳到算法名称，也不得在未说明物理来源时直接给经验公式。核心受力、投影、遮挡、轨迹、边界或状态关系若无法在三句内无歧义说明，必须生成机理图或几何图。

“求解过程”写计算逻辑和步骤之间的因果关系，不在本章展开完整公式推导、代码实现、参数表或数值结果。公式推导和具体计算放入模型建立与求解章节，最终数值和验证证据放入结果章节。

## 模型路线与克制思考（以图代文）

在说明模型选择与思路时，严格遵守 **“思考克制、大部分用图概括”** 的原则：

- **正文文字极度克制**：正文中对“为何选此模型、如何淘汰备选路线”的文字讨论控制在**一段话（150 字以内）**。仅陈述核心结论：“基于问题特征与[守恒/收敛]硬指标，主模型选用[模型A]；与[备选B]相比其[验证指标提升了X%]。”
- **大部分用图概括**：将复杂的模型思考、假设衍生关系、问题拆解与算法淘汰机制，**优先用关系图、决策树流程图或模型比较结构图替代**。
- **一图胜千言**：读者只需看图即可清晰理顺：`问题特征 ➔ 多候选路线 ➔ 淘汰依据 ➔ 最优模型决策`，正文避免冗长的比较流水账。

## 复杂思路强制流程图（国一模式）

用户目标为国一、国奖或一等奖时，完整读取
[../cumcm/references/national-first-precision-and-visual-gates.md](../cumcm/references/national-first-precision-and-visual-gates.md)。
只要当前一问包含三个以上不可合并阶段、判断/循环/回退/早停、粗搜—细化、状态转移、递归再生或多层输入输出，
就必须在该问分析末尾给出明确的分问题流程图；不能再以“正文已经说明”为由豁免。
流程图须能让评委在 10 秒内识别输入、核心变换、约束判断、更新与输出，并通过 `cumcm-diagrams` 的连接、布局和最终尺寸审查。
简单闭式代入或三句内能完整解释的路线可以不画，但必须在门禁 JSON 中记录豁免理由。

## 章末关系流程图

仅在文字难以清楚表达以下任一关系时加入：

- 前一问输出成为后一问输入；
- 多问共享同一数据、变量、机理或子模型；
- 多条分问路线最终汇合到统一决策；
- 后问对前问存在真实反馈或修正。

图中节点写具体对象、输入、关键处理或输出，如“问题一：参数识别”“几何边界”“问题三：方案优化”，
不用“进行分析”“建立模型”“得到结论”等空动作。箭头只表达真实的数据传递、时序、因果或反馈；
没有条件判断时不用菱形。问题关系以模块编排为主时优先 Visio 风格，符号、公式或可重复规则布局较多时优先 TikZ。

图必须保持白底、黑灰线、基础形状、克制配色和矢量输出，保留 `.vsdx`、`.drawio`、`.tex/.tikz`
等可编辑源。若各问只是并列且一段话即可说明，不画图。

## 严格禁写

- 再次重述题面或复制问题重述中的段落；
- 计算结果、最终答案、结果优劣和结论性数值；
- “意义重大、方法合理、效果显著、适用性强、具有推广价值”等开放性评价；
- 模型优缺点、改进建议、应用前景和与当前分析无关的延伸讨论；
- “为了便于理解”“使文章结构更清晰”“为后文奠定基础”等写作元叙事；
- “首先对问题进行分析”“通过上述分析可知”等无信息过渡句；
- 文件名、工作表名、代码、脚本、软件操作、审查门禁和内部试错过程；
- 不能回到真实求解记录的候选模型、求解步骤或验证安排。

## 门禁

写入 `审查/section-chain/gates/analysis.json`，至少检查：

- `fixed_heading_structure`：一级标题和逐问二级标题符合模板；
- `separate_from_restatement`：没有重复题面；
- `analysis_logic_complete`：每问的特征、思路和转化关系清楚；
- `solution_process_complete`：每问的真实求解链完整且步骤衔接明确；
- `question_dependencies_faithful`：只写真实存在的跨问关系；
- `no_result_leakage`：没有提前给出结果或结论性数值；
- `no_open_evaluation`：没有开放性评价、优缺点、改进或推广；
- `no_irrelevant_text`：没有空泛过渡、写作说明和无关内容；
- `no_production_trace`：没有文件、代码、软件过程或内部试错。

使用章末图时，另要求 `diagram_registry_pass` 和 `diagram_style_audit_pass`；未使用图时记录问题关系可由文字充分表达。全部通过后交给 `cumcm-assumptions`。
